# Issue #1093: HTTP API internal errors carry a trace id

## Added
- `telemetry::propagation::trace_id_of`: the OpenTelemetry trace id of a span, or `None` without a valid trace context.
- An internal `/api/v1` error's body gains `trace_id` (the request span's trace id), as an internal MCP tool error's has since #766.
- The console's error toast shows the trace id and stays 30 s (`toast`'s new `lingerMs`).

## Changed
- `mcp::current_trace_id` uses the shared `trace_id_of`.

## Notes
- No `X-Trace-Id` response header: only a failure needs the id, and the body is where clients read the error. Candidate follow-up if support needs ids on slow 200s.
- `OkfError::to_json()` is unchanged, so the detail never leaves the server; 4xx errors carry no `trace_id`.
