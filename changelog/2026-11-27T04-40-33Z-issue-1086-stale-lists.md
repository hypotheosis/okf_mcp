# Issue 1086: console lists stay current when a write finishes after navigating away

## Changed
- `teams.js`, `users.js` and `keys.js`: a write that settles after the user left the page and
  came back reloads the list of the page mounted now, through a module-level `mounted`, as
  `catalogs.js` does since issue 752. The old guard, `main.isConnected` of the page the write
  started on, was false by then, so the new page kept the old rows. Covers the create, member
  change and delete of teams, the create and delete of users, and the create, grant, ungrant,
  reporting, revoke and user changes of keys and sign-in codes.
- `teams.js`: the team Delete starts through `once` with the key `team:<name>:delete` and its
  button is guarded by it, so a second click, also in a drawer drawn again, sends no second
  DELETE.

## Added
- `tests/ui_e2e/teams.rs`, `users.rs`, `keys.rs`: one journey per page that holds the write,
  leaves the page and comes back, releases the write and expects the list to be up to date.
  The teams journey also checks that Delete sends one request.

## Notes
- The Unassigned view of the users page (`renderUnassigned`) still redraws only while its own
  `main` is connected; it is not changed here.
