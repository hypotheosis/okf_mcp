# Issue 656: a 404 or 410 on a CIMD URL fails closed

`CimdError::allows_stale_fallback` (`src/oauth/clients.rs`) no longer treats
404 Not Found and 410 Gone as failures the cache covers. When the client's
host answers either, the authorization fails at once with `invalid_client`,
even with a cached document inside the 24-hour ceiling. Every other 4xx, every
5xx and every network error keeps the stale fallback.

The cached row is left in place, not evicted, as for the existing fail-closed
cases (not JSON, too large): the next valid document replaces it, and the
24-hour ceiling still bounds it. A later transport failure can therefore still
serve it within the ceiling.

Tests: the table test gains 404 and 410 on the fail-closed side and 403, 429
and 503 on the fallback side; `a_missing_document_fails_closed_and_keeps_the_cached_row`
proves it end to end. Docs: the OAuth design spec's Cache bullet and
`docs/operations.md` state the rule.
