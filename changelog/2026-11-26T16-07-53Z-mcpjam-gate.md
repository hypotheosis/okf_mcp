# The MCPJam scenarios become a pre-merge gate

## What changed

- `tools/agentic/gate.sh mcpjam` runs `just test-mcpjam` under the shared gate
  lock with a 20-minute limit (`AGENTIC_TIMEOUT_MCPJAM`).
- The gate always uses local mode: it drops `OKF_MCP_URL`, `OKF_MCP_KEY`,
  `OKF_MCP_API_URL`, `OKF_MCP_ISOLATION`, `OKF_MCP_CATALOG`, `OKF_MCP_BIN` and
  `DATABASE_URL`, so it tests a server built from the checkout, on a throwaway
  Postgres. It keeps `TEST_PG_URL`, which points at a shared test server.
- `tools/agentic/brief-common.md` lists the gate as required before every
  push. `AGENTS.md`, `tools/agentic/README.md` and `tests/mcpjam/README.md`
  describe it.
- `tools/agentic/tests/run.sh` has four new tests: the gate runs the right
  recipe, it drops the target variables, a timeout returns 124, and it waits
  for the gate lock.

## Why

PRs have no CI by design: the gates run locally before each merge. The
MCPJam suite checks the MCP surface end to end without an LLM, so adding it
as a gate catches a change in what the server stores or answers before
merge. GitHub Actions CI was considered and not chosen.
